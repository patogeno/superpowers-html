Design Spec

Multi-Session Runs

1What it's for 2What you can do 3Screens 4How it flows 5Approaches 6Technical design

Big plans run as a roadmap of sessions, either overnight on their own or staged so you see each session before the next one starts. You can switch between the two at any point. You choose how the agents work (in parallel or one at a time, with one reviewer or a panel), and each session reads only the learnings it needs.

1. What it's for

Why. When there's a lot of work you run it as a multi-session plan, and you run it one of two ways: overnight, so it's ready when you wake up, or staged, so you can review and steer every session. Today the plugin has the multi-session structure but no way to run sessions back to back, no stop-and-show point between them, and one learnings file that grows until every new session reads all of it.

Goals

  • An overnight run finishes every session it can without you and tells you in the morning what it decided on your behalf.
  • A staged run stops after each session with a report you can read and answer from your phone.
  • You can go from staged to autonomous ("go autonomous until it's done") and back at any point.
  • You choose build speed and review depth separately, in plain words.
  • Each session reads only the learnings relevant to it.

Non-goals: scheduling runs for a later time, running across several machines, changing how a single task is built and reviewed.

It fails if: an overnight run pushes, deploys or deletes something; you wake up to a call you can't find or undo; a session repeats a mistake an earlier session already recorded; or a staged run starts the next session before you've answered.

2. What you can do

  • Pick how it runs, in plain wordsThe handoff states one line, like "Run: staged · Build: one at a time · Review: standard". Answer "overnight, fast" or "staged, thorough" to change it. Multi-session plans start staged unless you say otherwise. See it
  • Review each session (staged)A session report: what changed, how to try it, the calls made, what's next. Reply with feedback, "next", or "go autonomous until it's done". See it
  • Switch modes any timeStaged to autonomous, or "stop after this session" to go back. The roadmap records each switch. See it
  • Wake up to a night reportOne link, updated after every session so you can glance at it during the night. In the morning: what's done, calls made without you, what's waiting, how to try it. See it
  • See how hard calls were madeClaude takes the option that's easiest to undo. When a call is difficult, two fresh agents each argue for a different option before Claude decides. Both opinions and how to undo the call are in the report. See it
  • Trust the nightNothing outward or hard to undo happens unattended: no pushing, deploying, deleting data or sending. That work waits for you, listed in the report.
  • Learnings that stay smallA topic index, one file per topic that opens with "current truths", and a feedback file for what you've told it. Each session reads the index, its listed topics and your feedback, nothing else. See it

4. How it flows

One roadmap, run session by session. The only difference between the modes is whether it waits for you after each session.

Outward or hard-to-undo steps are parked in either mode and listed for you.

Learnings: each session reads a little and writes a little.

A topic file that grows long gets its history condensed into its current truths.

5. Approaches

How an overnight run moves between sessionsTrades off
A controller in your session starts a fresh lead per roadmap sessionClean context per session; switch modes with a reply; follow it from your phone; state on disk so a crash resumes.picked
A runner script starts a fresh Claude Code session per roadmap sessionSurvives anything, but headless permission setup, can't be followed from your phone, specific to one harness, and a script dependency.no
One session runs every roadmap sessionCheapest, but it's the context bloat multi-session plans exist to avoid.no

Calls Claude made

  • Claude's call A new skill instead of a reference file, so "continue the roadmap" in a fresh session triggers it from its description.
  • Claude's call Multi-session plans start staged by default: the safer start, and one reply makes it autonomous.
  • Claude's call "Outward or hard to undo" means: git push, opening or merging PRs, deploys, publishing packages, deleting data or files outside the work tree, sending messages, paid API spend beyond the session's normal use. Committing on the work branch is fine.
  • Claude's call The report is one artifact per roadmap, republished after every session, rather than one per session; its history section keeps earlier sessions.
  • Claude's call A topic file is condensed when it passes about 150 lines: history folded into "Current truths", the raw history kept in git.
  • Claude's call Claude Code's experimental agent teams don't nest under a subagent, so a parallel session lead uses ordinary parallel subagents.
  • Claude's call On harnesses without subagents, the controller runs each session itself in order and suggests a fresh session between them.
